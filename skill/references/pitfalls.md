# 触发条件—定位—修复—复验清单

前九项来自来源工程记录；后两项为官方接口语义推导的预防项，未声称来源工程确实发生过这些故障。来源编号见 evidence.md。

| 触发条件/表现 | 优先定位 | 修复动作 | 复验与边界 | 来源 |
|---|---|---|---|---|
| 名为最新版，但板端行为不同 | 核对 bit/HWH/软件指纹与 IP 契约；区分待加载文件与已加载 PL | 取回同次构建的完整载荷，停止旧控制者后重新验收 | 哈希相同只证明文件相同，不证明运行版本 | E1 |
| 复制目录后测试 FileNotFoundError | 找缺失配置/资源、相对路径和打包清单 | 补齐同版本依赖，改为入口相对路径 | 在独立目录完整复跑；不能只关掉失败测试 | E2 |
| 主机通过、板端 ImportError/接口缺失 | 对照 Python/PYNQ/NumPy 与 ARM 本机库版本 | 使用镜像环境；为新旧内存 API 分别适配 | 目标板 env + 最小功能检查 | E3 |
| 换接口版本后外设无响应 | bit/HWH、约束与实际连接器是否同版 | 断电后按目标板资料核对端口/电压/方向 | 不复制来源工程 PMOD/Arduino 引脚 | E4 |
| Vivado 退出码零，但无预期结果 | 查对应阶段 ERROR/FATAL、测试断言、产物和源指纹 | 修复原始错误，要求明确的阶段成功证据 | 不能仅凭搜到任意 PASS 判整个流程成功 | E5 |
| 波形路径不存在 | 查询真实仿真层级与对象，不猜顶层名字 | 依据当前层级添加信号，重新 run | 截图不代替断言；只验证所测对象 | E6 |
| 旧构建目录“秒通过” | 查旧 DCP/中间文件及源指纹 | 新空目录从脚本创建；保留新产物 | 源变更后重新运行相关层 | E5 |
| 显示/外设观察为空却写验收通过 | 查原始机器记录与独立人工观察 | 保留原 JSON，另附时间/观察者/原话 | 不以网页状态替代物理结果 | E7 |
| 对照吞吐异常、板端日期过旧 | 查冻结/操作/计数定义、单调时间和主机时间 | 固定输入和操作条件重做交替 A/B；保留原日期 | 不把显示刷新当任务完成，不将无效数据补零 | E8 |
| DMA 等待不返回 | 核对 TLAST/TKEEP、字节数、时钟/复位、状态错误、对齐与驱动版本 | 用项目支持的停止/复位机制，保存状态后排查握手 | CPU 超时不代表 DMA 已停止；未静止不可释放内存 | 官方 DMA 文档，预防项 |
| CPU 输出似乎“停在旧值” | 查连续内存分配、方向、缓存同步与实际完成标志 | 使用目标 API 和正确同步方向；检查驱动是否已自动同步 | 不能用延时 sleep 替代完成/同步协议 | 官方 Buffer 文档，预防项 |

Windows/Tcl 编码错误的来源案例曾通过 Tcl UTF-8 与原生工具入口完成重建。应先定位实际编码和调用链，不把强制修改 TCL_LIBRARY/locale 写成对所有 Vivado 版本适用的修复。
