# PYNQ 分层启动、缓存与清理

适用：以 bit/HWH 为载荷的 PYNQ PS/PL 工程。输入是目标配置、可信清单、原理图、接口文档、限时计划和项目驱动。输出是各层结果、原始日志和未通过的边界，不是某个特定题目的主程序。

## 层 0：不编程的检查

先 verify，再 env，最后 metadata；用目标镜像的 Python，不直接将电脑虚拟环境复制到板端。`download=False` 仅表示不下载 bitstream，不是功能仿真，也不确认当前 PL 版本。旧版本 Overlay/元数据 API 存在差异，要检查已装版本源码；不要用 `ignore_version=True` 掩盖未分析的驱动不匹配。

核对 bit/HWH 同名同目录、同一次实现、完整 part、板型、镜像、IP 地址表。对外连接另查目标板原理图、连接器方向、电压和 XDC。跨板需要重新构建，不照抄来源项目接线。

## 层 1：单一控制者与最小硬件

记录当前 Notebook kernel、后台程序和驱动资源占用，选择一个进程拥有 Overlay/DMA。停止旧任务并确认它退出，然后由项目入口显式加载经核对的 Overlay。不要在另一个 Notebook 内再次加载来“修复”运行中的任务。

先测时钟/复位和只读 ID/状态。寄存器偏移、位定义与读副作用必须来自自己的 IP 文档；读取 ABI 不适用于没有版本寄存器的 IP。没有 ABI 时登记无法确认的风险，不能编造通用版本地址。

## 层 2：缓冲区、协议和最小数据

使用镜像适配的连续内存 API。较新版本有 `pynq.allocate`；来源工程 PYNQ 2.4 使用的 Xlnk 路径应按旧镜像处理，不无条件替换为新 API。禁止把普通 NumPy 的虚拟地址当作 DMA 物理地址。

CPU 写输入后、PL 读前处理缓存同步；PL 写完且确认完成后、CPU 读前处理反向同步。新接口常用 `sync_to_device`/`sync_from_device`，对应 flush/invalidate，是否由 DMA 驱动自动处理需检查实际版本与通道实现，避免对不支持的方法直接调用。地址、对齐、数据类型、最大传输字节数和 DRE 配置也须核对。

先验证小块、全零、递增、边界值，再测实际负载；严格定义 signed/unsigned、大小端、定点小数位、饱和/截断、AXI 宽度和每拍有效字节。常见 AXI DMA 简单流协议需要正确 TLAST/TKEEP，但不能把 AXI DMA 的方法套到 AXI VDMA 或自定义 DMA。

采用项目协议允许的启动顺序。例如 AXI 流回环通常先准备接收再启动发送，以提供接收能力；仅在确认输入输出协议后这样做。DMA 两端字节数不一定相同，取决于 DUT 是否改变数据长度。

## 层 3：超时、停止与清理

不要把“在 Python 线程中调用 wait，等待线程超时”当作已停止 DMA。超时只是 CPU 的判定，硬件可能还在写内存。需要轮询时采用 `time.monotonic()` 截止时间，并在项目适配层检查真实完成/错误状态；如果驱动没有可靠的限时停止或复位机制，先补齐该机制，再做可能挂起的测试。

伪代码（仅是控制流程，不是可直接运行的驱动）：

```text
初始化所有资源变量，设置本次截止时间
try:
    加载已核对设计；申请输入/输出缓冲区
    写输入并同步；按协议准备通道、启动计算
    在截止时间内轮询完成/错误
    完成后同步输出；导出实际结果与计数、指纹
finally:
    请求停止生产者、停止 DMA/消费链，按 IP 手册确认静止
    仅在确认不再访问内存后释放缓冲区
    记录每一项清理失败；未静止则保留占用并走受控复位流程
```

有异常供电/明显异常升温时终止测试并处理硬件；上限以目标板/器件规范为准，本包没有统一温度阈值。不对有故障迹象的板卡自动重试压力测试。

## 层 4：持续运行与报告

先短时功能，再按验收计划延长。记录单调时间、独立任务计数、错误增量、温度和清理状态。计数回卷时按已知位宽处理；计数器复位不能当回卷。对照实验固定 bit、软件、输入、时钟、分辨率/数据大小、CPU 负载、温度和算法参数，交替测试、保存每轮样本。

界面状态不等于外设实际输出。人工观察单独记录观察人、时间和原话；无外设观察时填未观察。60 秒测试只证明对应 60 秒内所测条件，不自动证明长期稳定性、端到端延迟、功耗或光学效果。

## 官方接口依据（核对日期 2026-11-02）

- [当前 Overlay API](https://pynq.readthedocs.io/en/latest/pynq_package/pynq.overlay.html)：download 参数与 ip_dict 定义。
- [Overlay 实现源码](https://github.com/Xilinx/PYNQ/blob/master/pynq/overlay.py)：同名相邻 HWH 要求；目标镜像应查看其对应 tag/安装源码。
- [Buffer 与缓存方向](https://pynq.readthedocs.io/en/latest/pynq_libraries/allocate.html)：分配与同步语义。
- [AXI DMA 示例](https://pynq.readthedocs.io/en/latest/pynq_libraries/dma.html)：流传输与 TLAST；按实际驱动版本核对模式限制。

旧版 v2.4 的 Overlay 教程仍写 Tcl 元数据，而来源工程的本地 PYNQ 2.4 已验证 HWH 解析。故遇到文档版本差异应以目标安装源码和完整运行记录核对，不把“任意 PYNQ 版本都支持本脚本”作为保证。
