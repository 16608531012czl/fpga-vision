# 暗部彩噪处理

本文记录上一轮 CPU 合成管线的 balanced 方案及当时的颜色限制。
当前 PL 管线、细节优先预设、保色重建和实测状态见 [PL 升级说明](pl_upgrade_zh.md)。
下文“尚未实现”仅指该历史 CPU 方案。

本次保留现有FPGA硬件与时序，新增软件/摄像头ISP的balanced预设。
`--quality-preset baseline`恢复上一版ISP/增强参数，不启用颜色时域降噪。
二者使用同一分辨率与相机时序，实际帧率分别测量。

## 处理链与旋钮

摄像头ISP开启UV平均（0x5001 bit2），降低手动锐化幅度（0x5302=0x10），
提高锐化门限（0x530b=0x08）；保持DNS自动、AEC/AGC、增益上限、PLL与AF独立。
每次写入后读取验证。寄存器依据本地OV5640数据手册7.21/7.23。

对增强侧的活动图像执行ARM NEON颜色时域降噪；保留当前帧亮度，只混合颜色差分。
亮度或颜色变化超过门限时使用当前像素；高亮不混合。ROI、模式、强度、冻结变化和
超过0.2秒的帧间隔会清除历史。它不是光流补偿，低对比度细小运动仍需观察有无颜色残影。
首帧无历史可用，降噪至少从第二帧开始。黑边、OSD与左侧原图不经过该时域处理。

balanced默认：SH=2、DN=6、CT=0、NR=6，亮度B=0，算法GUIDED。
DN同时调节原有PL亮度降噪和新增颜色降噪，DN=0关闭两者；NR是锐化噪声门限。
长按恢复所选预设的默认参数。亮度、模式、冻结、缩放和短按选项保留。
自动提亮曲线沿用lowlight，避免把单纯降低亮度当作降噪效果。
摄像头ISP设置对原图和增强图都生效，因此左侧是ISP处理后的相机输出，不是RAW Bayer。

## 颜色偏淡的现有限制

用户实物反馈：彩点减轻，但增强侧的物品颜色比原图偏灰。当前COLOR重建为
`RGB输出 = RGB输入 + (增强Y - 输入Y)`，固定颜色差值在亮度提高后相对变小，
并且通道到255后的裁剪可能进一步压缩色彩差异。因此它不是严格保持HSV饱和度的映射。
颜色时域降噪也会压制细小的颜色变化；不能据“亮度保持”就宣称所有色彩完全保真。
GRAY/INVERSE/BINARY本身也不保留彩色，比较时先确认OSD显示COLOR。

后续应在降噪之后加入受限的色度补偿/色域压缩，或带低亮度保护的比例重建，
并用彩色物体与肤色作同场景验收。不能直接对R/G/B分别均衡或盲目提高饱和度，
否则可能引入色偏、饱和溢出和再次放大彩噪。此改进尚未实现。

实验用空间+时域颜色滤波核也保留在源码和板端逐像素测试中，实测开销更高，
实时balanced使用更轻的时域核，空间颜色预处理交给摄像头ISP。

## 验证边界

`reports/native_validation.json`给出ARM逐像素、非连续行跨距、边界保护区、
8像素NEON路径/尾部标量路径，以及同亮度合成暗块的噪声检查。
合成噪声指标不是实拍噪声或SNR；真实彩点、运动残影和文字锐度需物理显示观察。
板端JSON记录quality_preset、camera_quality回读、chroma_denoise_ms与独立FPS。
不得直接把原先baseline约19.8FPS作为balanced预设的验收结果。

启动示例（先退出另一份应用）：

```bash
sudo /usr/bin/python3 run_board.py --stage live --camera-fps 20 --mode color --quality-preset balanced --sharp-mode guided --no-sensors --af continuous --io-confirmed
```

如需更长单帧曝光上限作对照，另测`--camera-fps 15`。此举不保证更好画质；
自动曝光未到上限时也不一定变亮，应比较同场景的曝光、增益和实际画面。
