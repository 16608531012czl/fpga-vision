# 优化过程和可比性

早期 PS 侧处理减少 CPU 复制和查表更新；后续将实时缩放、分屏和文字组合迁移到 PL，以降低逐帧软件工作量。相机时序配置与 ISP 细节也经历调整，因此历史 FPS 的变化包含多因素，不能把整个增幅归因于某个算子。

| 阶段或对照 | 前项 | 后项 | 说明 |
|---|---:|---:|---|
| 历史采集 FPS | 10.707 | 16.618 | 原始记录报告约 55.2% 趋势提升；场景/操作不同，非严格 A/B |
| 历史进一步 PL 链路 | 16.618 | 19.971 | 不同版本和场景，仅展示工程演进 |
| 本次采集 / 渲染 FPS | 19.980 | 19.622 | 同一次运行的两种计数，包含冻结，不能解释为 AUTO 开销 |
| LUT（10-28 硬件 / 10-30 AUTO） | 9957 | 9957 | 18.72%，复用同一 bit |
| FF | 12443 | 12443 | 11.69%，同一 bit |
| BRAM tile | 40 | 40 | 28.57%，同一 bit |
| DSP | 38 | 38 | 17.27%，同一 bit |
| 建立/保持裕量 ns | 0.189/0.014 | 0.189/0.014 | 同一 bit 对应原报告，DRC 错误 0 |

可直接确认的最新改进是控制策略：AUTO 将局部对比度、色彩补偿、二值化阈值和窗口等纳入联动，按 9 个 24×24 ROI（5184 像素）估计场景，限速更新并保留手动接管。当前实测 contrast 从 1 到 2、color 从 9 到 10，手动值保持与恢复 AUTO 通过。软件策略改变没有新增 PL 资源，依据是 bit/HWH 指纹相同，不是估计综合结果。

历史 PL 记录 LUT=9945、FF=12394；当前 Arduino 接口版为 9957/12443，版本不同，不能混填为当前资源。资源表采用当前 bit 对应 10 月 28 日布线报告；本次从源码重建若得到不同物理实现，应单独报告，不能替换板端证据绑定。

完整机器可读表见 `../data/optimization.csv`。AUTO 固定场景开/关、端到端延迟、功耗、阅读速度和清晰度客观评分仍未测；严格对照协议见 reproduction.md。对功能完成度和已取得结果作结论，避免扩大成临床效果或硬件极限。
