# 下一轮 PL 升级的可行性与实施顺序

本文件保留升级前的设计建议。现阶段实现、限制与验收入口见 [PL 图像链路说明](pl_upgrade_zh.md)。
本文件中的旧资源数值为升级前记录，不代表新版本。

## 已有基础与容量

当前布线报告 `reports/system_utilization.rpt`：LUT 6307/53200（11.86%），
寄存器10287/106400（9.67%），BRAM 23/140（16.43%）。容量上有扩展空间，
DSP12/220（5.45%）。
实际新增资源与时序必须重新综合、布线确认。100MHz流水线不是摄像头已实测帧率。

已有PL功能：DVP跨时钟采集、AXI写DDR、显示侧逐像素亮度映射、15×15局部均值、
3×3亮度降噪、Sobel/Laplacian/边缘门控锐化，以及15×15局部均值减C的自适应二值化。
ARM仍承担ROI裁剪、缩放、分屏合成、OSD及帧级参数更新。

## 第一阶段：PL缩放与分屏合成

先保留DDR双/三缓冲，逐步替换ARM图像搬运，避免同时重写采集与显示同步。
可从显示VDMA的1280×720原图流进入新模块：二倍降采样 → 640像素行缓存 →
按显示坐标输出同一行的左右副本，在上下区域补黑边 → 原图/增强选择 → OSD → HDMI。
双行缓存必须在输入、输出独立握手下保持行号和数据所有权；不能只把像素流分叉后直接拼接。

上述是功能划分，不表示“两行缓存一定足够”：纵向二倍缩小要消耗两行输入才产生一行，
中间360行还要连续输出左右两份。需按100MHz处理时钟、实际AXIS停顿及HDMI时序
核算最坏行吞吐与预取深度。若行缓存方案不能持续供数，可先在DDR保存缩小后的中间帧，
或增加预取行、采用输入每周期两像素等方式；不可用忽略反压或重复错行换取出图。

固定二倍缩小先用2×2盒式抗混叠；随后扩展双线性比例缩放、ROI平移与1/2/4倍变焦。
参数在SOF生效；原图与增强必须使用同一帧、同一个ROI。保留冻结功能与帧编号。
ARM只写参数、状态和少量OSD信息。摄像头20Hz与HDMI60Hz仍通过帧缓冲解耦。

验收：原图像素/缩放误差、帧与行边界、随机反压、连续流、冻结/缩放切换、DDR带宽、
无撕裂、真实独立采集FPS和端到端延迟。现有高帧率输入的坏行问题不能由合成模块自动修复。

## 第二阶段：分块亮度映射

开始前先解决用户已观察到的COLOR提亮后颜色偏灰：降噪之后用受限色度补偿/色域压缩
改善相对饱和度，验证肤色与彩色物体。局部映射也必须沿用这一保色策略。

建议先做8×6分块、每块64级亮度统计。1280×720时每块160×120，统计计数至少15位。
只对Y做单调映射，颜色差分由独立、受限的保色重建处理。每像素读取四个相邻分块LUT并做双线性插值，
处理图像边缘与块中心坐标，避免硬切块。

每块加入直方图限幅、暗部增益/映射斜率限制、亮部保护；映射结果做时间平滑。
先用上一完整帧的统计映射下一帧，并在SOF切换双缓冲LUT。每次处理的帧只积累一次统计，
不要把HDMI重复刷新当作新相机帧。镜头切换/快速亮度变化要重置或加快映射响应。
这会有一帧的统计滞后，不等同于整条图像链路多缓存一帧。若要求当前帧统计当前帧映射，
需增加DDR读写或分块缓存及对应延迟。

8×6×64×15位直方图单份为46080位；双缓冲92160位约11.25KiB。
8位输出LUT一份24576位，双份约6KiB。这只是原始数据容量，不是最终BRAM利用率；
多端口读、直方图连续相同bin的读改写冲突、LUT复制/分银行会增加资源。
完整256bin CLAHE可作为下一阶段，而非首版必选。CLAHE限幅也不能代替降噪。

## 第三阶段：阅读二值化升级

先开放局部均值窗口和阈值C，并改进当前因果窗口的定位/边界策略。
可做15×15和31×31档位，再根据文稿阴影、纸张纹理和笔画断裂情况决定是否引入
局部方差的Sauvola近似。平方和、开方/查表与更大行缓存需要单独资源和时序评估。
二值化用在文字阅读模式；彩色暗光显示继续使用保色提亮与降噪。
