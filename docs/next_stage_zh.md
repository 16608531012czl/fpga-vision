# 第一阶段交付与下一阶段

当前第一阶段实现EC11硬件解码、手动亮度偏好、USM/Laplacian/GUIDED对照、Sobel诊断、降噪档位与状态显示。
配置在帧边界生效，左侧保持同帧原图；自动Gamma不会覆盖用户的锐化等设置。
用户已观察到旋转时数值和画面明显变化，并确认短按后EDIT切到SHARPNESS、SH数值可调。
最终编译、发布包和实板结果分别见build_manifest、delivery_manifest和board_validation_20261022。

## 先补齐的验收

- 光照模块仍无有效lux，原接口复测报SCL held low；本版以图像统计回退并显示LUX ERR。
- 本次按用户要求改为PMOD B：SCL→物理第3脚、SDA→物理第4脚；需新FPGA文件及实测验收。
- EC11为S1→AR8、S2→AR9、KEY→AR10，供电3.3V并共地。
- 借万用表后先测模块VCC-GND和总线释放时电压，再逐条排除供电、跳线和外部负载。
- 暂不认定板卡或模块损坏；已有逻辑读回不足以测出实际电压。
- 用固定纸面、细字、平坦背景和强边缘保留真实对照照片；软件预览不替代板上照片。

## 其余3～4周的建议顺序

1. 第一周：补齐光照通信、固定场景暗光对照、旋钮每格计数和长时间运行记录。
2. 第二周：做亮度分区或局部映射，针对暗处文字与亮背景共存的场景；先比较阴影细节、噪点和高光。
3. 第三周：根据实际耗时优化ARM合成和LUT更新；再评估把ROI缩放等移入PL，逐项量资源与帧率。
4. 余下时间：冻结功能，保存可回退包、统一演示场景、验证连续运行与答辩材料中的所有数字。

不要把标准Sobel、Laplacian或USM描述为独创算法。比赛贡献可围绕实际系统中的噪声约束、联合控制、实时交互和验证展开。
曝光闭环属于独立升级：OV5640自身AEC与外部闭环需要明确分工，不能同时无约束追同一亮度目标。
上述阶段尚未实现，不写入本版已完成功能。

## 文件用途

board.zip是板端运行包，不需要在PYNQ上安装电脑端依赖。
source.zip用于本机继续开发，包含源码、生成脚本、配套硬件和验证记录；跨电脑构建前需配置Vivado路径及受保护基线。
旧V3原工程保留。编译清单是生成时的记录，实板通过项以单独运行报告和用户物理观察为准。
